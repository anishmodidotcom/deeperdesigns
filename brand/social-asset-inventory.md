## ProductFragment glyphs

**One file, per-slug `switch` cases.** Path: `app/_home/ProductFragment.tsx` (420 lines, 22KB).

- Each case returns a React component built from `<div>` + `<svg>` + inline CSS — **not standalone SVG**.
- The fragments reference CSS custom properties (`var(--accent)`, `var(--bg-card)`, `var(--fg-muted)`) defined in `app/globals.css`. Out of that runtime context the colors are unresolved.
- They use `<Image>` from `next/image` in zero places — pure CSS / SVG primitives. Good for crisp rasterisation.
- **Extractable as standalone SVG: no.** The cleanest path for the content engine is to render the homepage at `/#gallery`, locate the per-card glyph by selector, and screenshot it. Each card is square (aspect-ratio 1 / 1) inside a `.gallery-card` element.
- All 22 slugs have a `case`; the `default:` branch is a dashed circle (placeholder).

## Fonts

**No font files in the repo.** No `.ttf`, `.woff`, `.woff2`, `.otf` under `app/`, `public/`, `brand/`, or `components/`. All fonts load at request time via `next/font/google` (see `app/layout.tsx:2`).

The site uses three families globally, loaded in `app/layout.tsx`:

| Family | next/font subset | Variable | Weights / styles loaded |
|---|---|---|---|
| Geist (Sans) | `["latin"]` | `--font-geist-sans` | All weights (variable font) |
| Geist Mono | `["latin"]` | `--font-geist-mono` | All weights (variable font) |
| Instrument Serif | `["latin"]` | `--font-instrument-serif` | weight `400`, styles `normal` + `italic` |

Per-showcase pages load additional Google Fonts locally (Anton on zara-fitness, Fraunces on malabar-spice, etc.) — those are showcase-internal and not part of the brand voice for social graphics.

**Content engine must source these fonts externally — all three are on Google Fonts (free):**
- [Geist](https://fonts.google.com/specimen/Geist)
- [Geist Mono](https://fonts.google.com/specimen/Geist+Mono)
- [Instrument Serif](https://fonts.google.com/specimen/Instrument+Serif)

If the engine renders to PNG via headless browser, it can just include `<link href="https://fonts.googleapis.com/css2?family=Geist:wght@400;500;600;700&family=Geist+Mono:wght@400;500&family=Instrument+Serif:ital@0;1&display=swap" rel="stylesheet"/>` in its template. If the engine renders via a non-browser pipeline (Pillow, Cairo, etc.), download the .woff2 / .ttf from Google Fonts and bundle them as the engine's runtime asset.

## Recommended pipeline approach

The content engine should treat the site as the source of visual truth, not a parallel asset library. Import `brand/v1/logo/*.svg` (wordmark + monogram) directly into every output; pull `public/images/_ambient/*.webp` and the per-showcase hero / portrait / detail webps directly when a post is about that showcase — they're already cropped to common social aspects (1080×1350 portrait, 1920×1080 landscape, 1024×1024 square, 1080×1620 vertical hero). For posts about the product mockup itself, run Playwright against the live URL: navigate to `/work/{slug}`, scroll to the named signature component (e.g. `hivedesk/Dashboard`, `stumpvision/Card`), and screenshot the element — never recreate the mockup in a separate tool. Source the three brand fonts from Google Fonts at render time; do not bundle, do not substitute. Per-showcase secondary fonts and third-party tool logos are out of scope for DD social graphics — keep them on the site only.
